# Config folder

Copy this folder to wherever you keep configuration (for example `/opt/subtitle-config`) and mount it into the
services (`/config`). Everything in it is optional; a missing file simply means "use the defaults".

```
config/
  schemas/            JSON Schemas: defaults, allowed values, descriptions, the environment variable of each
                      setting (x-env), secrets (x-secret) and "applies after restart" (x-restart).
                      Generated by subcfg/gen_schemas.py; the web UI builds its forms from these.
  npusubs.json        speech service settings (beam, VAD, music, diarization, subtitle rules)
  bridge.json         bridge settings (backends, LLM, translation passes, filters, Sonarr/Radarr)
  settings.json       shared settings (resource guard)
  profiles/*.json     per show / path / language overrides (first match wins)
  secrets.env         (copy secrets.env.example) NAME=value, chmod 600; referenced from JSON as "${NAME}"; never put secrets in the JSON files
  history/            snapshots of replaced files, written when settings are saved through subcfg/the UI
```

Precedence, lowest to highest: schema defaults, the component's JSON file, **environment variables**, a matching
profile. A non-empty environment variable always wins over the file; leave them unset (or empty) to manage a setting
from the file. `GET /config` on the bridge and `/health` on npusubs show where each value comes from.

Changes to a file are picked up within a few seconds, without a restart. Settings marked `x-restart` (the Whisper
model, thread count) need a restart. An invalid file never breaks a running service: the last good configuration stays
active and the problem is reported (`errors`).

## The web UI password

Nothing to configure: the first time you open the bridge's `/ui` it asks you to choose a password (stored hashed in
`auth.json` in this folder, which therefore has to be writable). Forgot it:
`python subcfg/subcfg.py reset-password --dir ./config`. Scripts can use an optional API token
(`python subcfg/subcfg.py init-token`). Details: [docs/web-ui-getting-started.md](../docs/web-ui-getting-started.md).

## From environment variables to files

```bash
python subcfg/subcfg.py seed bridge --dir ./config      # JSON for what the environment currently sets (secrets as ${NAME})
python subcfg/subcfg.py show bridge --dir ./config      # every setting, its value and its source
python subcfg/subcfg.py check npusubs --dir ./config    # validate a file
```

Then remove the migrated variables from your compose file. Secrets belong in `secrets.env`.

## Profile example

```json
{
  "name": "anime-ja",
  "match": { "path_glob": "*/Anime/*", "source_language": "ja" },
  "overrides": { "npusubs": { "beam": 5 }, "bridge": { "translation": { "keep_honorifics": true } } }
}
```

Profiles are tried in file name order (`10-anime.json` before `20-series.json`), the first match wins. `match` can use
`path_glob` (the media path Bazarr sends, with `*` wildcards), `source_language` and `target_language` (for a Bazarr
translation task the target is `en`); all given fields must match. They are edited in the bridge web UI (Profiles tab),
which also shows which profile applies to a given path.

What a profile can change per job: **every bridge setting**, and of npusubs the beam, `vad.enabled`,
`diarization.default` and `subtitles.*` (the bridge passes the media path to npusubs). Other npusubs settings (model,
music detection thresholds, queue) stay global. Jobs that need different profiles run one after the other, never at the
same time, because a profile changes the bridge's settings for the duration of the job. Deleting a profile keeps a copy
in `history/profiles/<name>/`.
